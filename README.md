# ORBIT RELAY · 星环接力

一个 2–4 人局域网实时合作游戏。每位玩家使用自己的浏览器，通过五位房间码加入；Node.js 服务器统一计算世界状态，浏览器负责输入和绘制。

## 启动

需要 Node.js 22 或更新版本。Windows 上双击 **`start.cmd`**：首次运行会自动安装项目依赖，之后直接启动；服务器就绪后会在默认浏览器打开游戏页面。终端会显示本机和局域网地址，游玩期间保留该窗口，按 Ctrl+C 停止。

也可以在项目文件夹打开终端后手动启动：

```powershell
npm ci --no-audit --no-fund
npm start
```

本机打开 **http://localhost:3000**。其他设备连接同一局域网，打开启动终端列出的 **LAN 地址**；换网后地址可能改变。

1. 输入呼号，创建房间。
2. 其他设备打开同一台服务器的 LAN 地址，输入房间码；也可以用「复制邀请链接」。房间码不能跨不同服务器使用。
3. 至少两人加入，所有在线玩家点击准备，由房主启动。
4. 键盘 WASD / 方向键移动，E 拾取、投递或沿朝向抛出，空格 / Shift 冲刺。手机使用摇杆和两个操作按钮；横屏时战场与按钮同时显示。
5. 结算后所有玩家重新准备，由当前房主开启下一局。

关闭服务器终端或按 Ctrl+C 会结束所有房间。更换端口：

```powershell
$env:PORT = "3001"
npm start
```

不需要打包步骤，不依赖外部字体、图片、CDN 或云服务。程序同时提供网页和 Socket.IO，禁止只将 public 目录作为单机静态网页打开。

## 玩法

150 秒内把 18 个能量核送至匹配颜色与形状的泊位，并维持反应堆稳定度。核心每 9 秒释放三枚，共六批；场内积压过多时延后释放。三种标识分别是绿色三角、蓝色菱形和琥珀圆形。

- 接住队友抛出的核心再投递：额外恢复 4 点稳定度。
- 8 秒内连续投递：最高 5 连击，额外恢复稳定度。
- 每 13 秒出现一轮外扩干扰波，先有 2 秒预警。受击会掉核、眩晕并损失团队稳定度。
- 冲刺冷却 3.2 秒，带短暂免疫。可以用来穿过干扰波。
- 携核时会略微减速；玩家可互相穿行，不会因队友挡路卡住。
- 1/2/3 或手机「呼叫」菜单发送「这里！」「漂亮！」「收到」。局中底栏显示连击、接力与最新事件；携核时箭头提示抛出方向。音效默认关闭，可点击右上角开启。

## 多人同步与恢复

服务端以 30 Hz 固定步长模拟，15 Hz 发完整房间快照；交互成功额外立即同步。客户端只发送方向、操作与递增序号，不能上传坐标或分数。移动过期 300ms 后自动停止，动作去重，抢同一核心由服务器串行裁定。

连接与身份分离：每个席位有随机恢复令牌，只返回本人并保存于当前标签页 sessionStorage。掉线后 90 秒内原标签页刷新/重连，恢复身份、位置、分数和最新世界；携带的核心在掉线时释放，避免队伍被离线玩家占用资源。新设备是新席位，不能仅靠昵称接管他人。

房主掉线自动转交开局权；若房主在线，但从最近一次大厅变化（成员加入/离开/断线/重连、准备状态变化、回合结束、倒计时取消）或房主自身操作算起 30 秒没有动作，至少两名已准备的队员可接管。这些大厅变化会重新计时，因此刚加入或刚点准备的成员不会立即接管。双人房里若房主挂机且未准备，唯一的队友无法单独接管开局；请再邀请一位准备好的队友，或离开后新建房间。房主可在大厅或结算后移除挂机席位；离开和移除均需确认。中途加入或重连游戏中的玩家有 1.2 秒出生保护。所有玩家掉线后游戏时间暂停；最后一个席位退出或过期时清空旧对局，空房 5 分钟回收。服务器重启会清空所有房间，网页会明确提示恢复失败。没有数据库持久化或跨服务器会话迁移。

## 测试

```powershell
npm run check
npm test
# 先在另一终端启动 npm start
node scripts/verify-round.mjs 2
node scripts/verify-round.mjs 4
```

规则与协议测试包含：同时抢核、一次投递只计分一次、错误泊位、接力奖励、速度/碰撞/冷却、分批供给、胜负与重开、席位上限、房间隔离、房主权限、输入校验、重连令牌和过期处理、广播隐私，以及 3000 步随机操作下的核心归属不变量。

整局测试用真实 Socket.IO WebSocket 连接，全部通过公开输入协议操作，**不修改服务器坐标、分数或计时**。包含中途断开一位玩家、重新认证、通关及重开。

`npm run test:browser` 是可选的原生 Chrome CDP 验收脚本，只使用本仓库内的连接代码和本机 Chrome；先启动游戏服务器，再在另一终端运行。脚本使用 9222 端口和独立测试页面，检查键盘/触屏同步、刷新恢复及房主空闲接管；设置 `QA_VERIFY_MINIMIZED=1` 可额外验证最小化窗口恢复。截图生成在不上传的 `artifacts/`，脚本不会关闭 Chrome 或标签页。若 Chrome 显示配置文件选择页，请先选中 ChromeDebug 中已有的测试配置文件；其他机器可用 `CHROME_PATH` 指定 Chrome 路径、`CHROME_USER_DATA_DIR` 指定测试配置目录。

## 局域网排障

- 手机不能使用 `localhost`：那指的是手机自己，需使用服务器电脑的 LAN IP。
- Wi-Fi 和访客 Wi-Fi 可能互相隔离。确认设备位于可互访的局域网；部分热点/路由器启用客户端隔离。
- Windows 若询问 Node.js 网络访问，请只对你信任的专用网络授权。本项目不会自动修改防火墙。
- 多网卡时页面的「局域网连接地址」列出候选地址，并可选择复制邀请时使用的地址；优先 Wi-Fi / 以太网，不要选代理、VPN 或虚拟网卡。
- `/api/health` 可检查服务可达性。若端口被占用，用 `PORT` 切换，所有玩家必须使用同一地址与端口。
- Windows 受限执行沙箱可能允许监听却阻止连接；应在获准网络访问的终端启动服务。正常用户终端运行 `npm start` 不依赖 Codex 沙箱。

## 文件结构

```text
game.mjs                 权威规则与房间状态
server.mjs               HTTP、实时协议、身份、限流、房间隔离
public/shared.js         两端共享地图和规则常量
public/app.js            界面、连接、恢复状态机、键盘/触屏/音效
public/renderer.js       Canvas 世界、插值平滑、粒子与光效
public/index.html        可访问的 DOM 界面与引导
public/style.css         桌面、平板、手机布局
test/                    规则与真实网络集成测试
scripts/                 整局和浏览器验收脚本
DESIGN.md                方案取舍、架构评估、分阶段验收标准
VERIFICATION.md          当前版本实测结果与边界
```

本轮没有公网部署。公网阶段需要 TLS、WebSocket 代理配置、访问控制、容量测试、监控与持久化策略；房间码不是隐私密码。
